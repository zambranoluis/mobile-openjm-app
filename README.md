# OpenJM native app

Expo SDK 57 / React Native mobile application with repository-owned requirements, contract snapshot, test criteria and assets. Current delivery targets Android emulator/private APK; iOS delivery is deferred. Live integration is unavailable because the current backend has no native gateway producer compatible with the retained client snapshot. Source, export and fictional fixture checks do not establish native parity or live readiness. `tests/criteria/` owns standing parity mappings and asset identities; task records contain only run-specific progress and evidence.

Install Node 22.13 or later and reproduce pinned dependencies with `npm ci` when setup is authorized. Only the public API origin belongs in Expo configuration; secrets never do. Use the bounded fictional fixture under the test guide for local emulator checks. A future real gateway requires explicit producer compatibility and approved HTTPS/QA access before configuration or integration. `npm start` starts the development client; `npm run android` requires a configured Android SDK; iOS needs macOS/Xcode or a signed EAS build. Web preview is auxiliary evidence.

Run `npm run check`; dependency/native configuration changes additionally use `npx expo install --check`, `npx expo-doctor`, and an applicable export/build. Regenerate provider adapters with `npm run instructions:generate` after canonical guidance changes. Normal parity, asset and snapshot checks require no task records or sibling checkout. Coordinated inventory/hash refresh uses `npm run inventory:web -- EXPLICIT_WEB_ROOT` then reviewed mappings and `npm run parity:generate -- --web=EXPLICIT_WEB_ROOT`; asset comparison uses `npm run assets:check -- --source`. Compare the snapshot only with an explicitly supplied compatible producer specification; the retired gateway path is not a current runnable prerequisite. [Tests](tests/README.md) defines lane limits.

Native refresh credentials and stable installation ID use SecureStore; access tokens remain in memory. Drafts are scoped by account and conversation in local device storage. Sign-out blocks local access immediately, attempts server revocation and device credential removal, and reports failures for retry. A credential-free local marker prevents restart from restoring a failed SecureStore deletion; unreadable marker storage fails closed. The app never interprets a checkout return as payment confirmation. Reopen reads authoritative server state.

Private release prerequisites: staging HTTPS, designated QA accounts, Expo/EAS project and login, Apple distribution signing/provisioning and registered iPhones, Android/iPhone test access, push configuration. Supply secrets through local/EAS secure configuration. `eas build --profile staging --platform android` and its iOS counterpart require those prerequisites; no release has been uploaded. Hosting and Git publication require separate direction. Public stores, store billing and tablet layouts are deferred.

Completion alerts are opt-in under Account. The public `EAS_PROJECT_ID` identifies the matching signed Expo project; provider credentials and optional Expo service authorization stay server/EAS-side. Native dispatch is unavailable in the current backend. Select “Notify me” on a response or image/video/music job; alerts contain no conversation text and open an authenticated account-bound result by resource type. V41 and a compatible native build are required for media dispatch. Actual provider/device delivery remains acceptance work.

The Windows wrapper generates local autolinking with paths normalized to its verified temporary drive alias and uses separate CMake slots. This avoids mixed physical/alias roots after native regeneration; old caches remain retained. Set `JAVA_HOME` explicitly to Android Studio's compatible runtime when your normal Java is used by Spring.

On Windows, use `pwsh -File scripts/android-build-local.ps1` for a local x86_64 emulator development APK. `-Bundled` embeds JavaScript using the generated release variant; the generated Android signing configuration still uses a debug certificate, so this is local test evidence, not a distribution release. `-Architecture arm64-v8a` targets modern Android phones. The wrapper checks configuration, generates native files if absent, uses a temporary unused drive alias and compact CMake staging path, and bounds compilation. It preserves previous native caches and does not change Windows-wide long-path settings. Android Studio's Java 21 runtime and its SDK are the observed local toolchain. Both APK variants need separate installed checks; an export is not an iOS build.

Saved conversations expose media generation/results and their associated file library. Image/music availability comes from the model catalog; the current video-generation and voice release restrictions remain. Media reads/downloads use authenticated bounded transfers (24 MiB), then private cache files and native players/share sheets. Music request UUIDs and recent identifiers are account-isolated; authoritative conversation media also recovers results created elsewhere. Playback pauses on route exit/background. File images use vision purpose and8 MiB limits; document transfers use24 MiB. Anonymous chat uses independent public gateway mappings, an anonymous session and local draft, without bearer or upstream credentials. It preserves partial interruptions and never automatically resubmits.

Math uses local KaTeX markup, embedded WOFF2 fonts and an isolated formula WebView with denied external navigation, file/network access and untrusted commands. Formula expansion/size and widget count are bounded; unsupported/large/additional formulas remain selectable source. The auxiliary web preview displays formula source. Run `npm run math:check` after a reviewed package update; regenerate with `node scripts/math-assets.mjs --write`. Retained license: [KaTeX](assets/licenses/KaTeX.txt).

Language selection is available from welcome and Account. English, Spanish, Portuguese, Hindi, Chinese and Russian use219 retained/native common entries, with original server/user text preserved. Native-specific copy still falls back to English and requires translation review; the selector makes that limit explicit. `npm run locales:check` checks retained entry completeness, not whole-interface translation acceptance.

Account includes server-validated profile photos and OTP-protected deletion with explicit typed confirmation. Conversations includes response-job creation, status/result/cancellation and integer-cursor following, plus embeddings with complete JSON sharing. Prompt complexity and stream mode come from Spring. Public image/music generation, job status/content and chat attachments use resource credentials stored in secure chunks; metadata contains identifiers rather than tokens. A persisted cleanup journal supports retry after interrupted credential removal. These operations have independent fixture and live acceptance limits in the capability matrix.

JSON responses are bounded to16 MiB and binary responses to24 MiB. Private streams reject delivery after the account session changes. Long forms reveal the focused input when the keyboard appears. `node scripts/artifact-inputs.mjs create ABSOLUTE_SELECTED_TASK_OUTPUT/<revision>-inputs.json --output-root ABSOLUTE_SELECTED_TASK_OUTPUT` freezes source hashes without overwriting an earlier record; `verify` uses the same output root and checks for additions, removals and changes before preserving that artifact.

Binary read failures discard partial content and show a recoverable interrupted-download message without raw native diagnostics. A retry requires a user action. Native form scrolling rechecks the focused field after the keyboard resizes its viewport; installed and large-text coverage remains operation-specific.
