# Native verification

Run `npm test` for Jest/jest-expo and React Native Testing Library, `npm run test:unit` for pure transport/storage behavior, and `npm run contract:check` for the local versioned snapshot. The mobile repository builds without a sibling checkout. A coordinated boundary check compares the snapshot with the gateway-owned specification explicitly; never import sibling source.

Fixture tests use deterministic fictional data and are not live integration proof. Live tests use designated QA accounts and staging HTTPS supplied securely. Keep tokens, passwords, private responses and screenshots out of tracked fixtures. Store generated evidence under `test-artifacts/runs/<run-id>/` with commands, platform, OS, device and result manifest.

Run `maestro test tests/maestro/guest.yaml` against an installed bundled app. `guest-actions.yaml` is a shared subflow. Development-client bootstrap flows require an explicit `DEVELOPMENT_URL` and reachable packager; their launcher setup is separate from native product acceptance. Do not run the whole directory indiscriminately. Pin phone model, OS, theme, font scale and locale for visual comparisons. Wait for settled rendering; inspect screenshot differences before accepting approved baselines in `tests/baselines/`. EAS testing may run the installed-app flows when configured.

`node tests/fixtures/server.mjs` starts an explicit fictional, loopback-only service on 8097 with no upstream connection. For an Android emulator fixture build, set `EXPO_PUBLIC_MOBILE_API_URL=http://10.0.2.2:8097` only in that build process. Use a separate, clearly labeled fixture APK/artifact record. The fixture covers fictional MFA/history/SSE/reset, billing redemption and plan purchase, preferences/usage, OTP export/key/installation/memory actions, and domain pending/verified states. Unimplemented fixture operations reject with 501; archive/media payloads are separate checks. Use the bundled flows for the matching APK revision; `fixture-sign-in.yaml` is a reusable setup flow. Its responses are not domain availability or live proof. `fixture-core.yaml` currently uses development-client bootstrap and remains a source flow until installed execution is recorded.

For the separate bundled fixture package, set `OPENJM_FIXTURE_BUILD=1`, `APP_ENV=development` and exactly `EXPO_PUBLIC_MOBILE_API_URL=http://10.0.2.2:8097` in the build process. Regenerate Android with `npx expo prebuild --platform android --no-install`, then build with the local wrapper and `-Bundled`. This package is `com.openjm.mobile.fixture`, labelled OpenJM Fixture, and permits local emulator cleartext only as a development fixture. The release-stage gate rejects fixture configuration. Install it and run `maestro test tests/maestro/fixture-bundled.yaml` with the fictional server already running; this flow does not need Metro or a development deep link. Extra fixture reads cover profile/security, unavailable alert status and reset completion. Record the actual result before treating this source flow as executed.

Required integration scenarios: login/MFA/profile completion; restart, refresh races, expiry, revocation/logout; unauthorized conversation/job access; duplicate and simultaneous web/mobile submissions; shared active attachment, replay expiry, Redis/backend interruption; network changes, background/reopen, upload interruption, cancellation and result retrieval; checkout cancellation/pending/completion; denied push, deduplicated outbox/receipts, invalid registrations, logout and authenticated deep links.

Required device scenarios on both OSes: small phones, large text, long responses, keyboard visibility, safe areas, screen readers, reduced motion, permissions, file sharing/downloads, media, notification delivery and installation. Emulator checks do not replace physical-device evidence for permissions, notifications, gestures and performance. Do not approve native screenshots from a browser export.

R4 bundled fixture source adds `fixture-media.yaml`, `fixture-anonymous.yaml`, `fixture-files.yaml` and `fixture-math-language.yaml`. Run them separately and retain failures as well as corrected runs. Media uses a fictional image and a deterministic 30-second WAV tone; this does not prove live generation, production codecs or physical-device audio. Native formulas render locally with KaTeX; screenshots and source fallback require installed inspection. Language selection preserves six languages with partial native translation coverage, so selected translated screens are not whole-interface acceptance. OS share-sheet labels must come from observed installed UI. No R4 flow is considered passed until its actual result is recorded.

Use `OPENJM_FIXTURE_AUDIO_SECONDS=300` for an early background-pause check; the server supports30–600 seconds. A capture at the end of the track cannot prove early pause. Background and restore the same Android task through observed Recents UI, then run `fixture-media-reopen.yaml`; retain playback progress below the track duration. R5 source flows `fixture-r5-sign-in.yaml`, `fixture-utilities.yaml` and `fixture-photo-delete.yaml` exercise keyboard-visible OTP without password reuse, jobs/embeddings and OTP account deletion. Run only against the matching R5 or later fixture artifact; assertions in a source flow are not executed evidence. Native photo picking/upload, public attachments, iOS and live owners need separate acceptance.
